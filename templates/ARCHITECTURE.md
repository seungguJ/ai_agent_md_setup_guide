# ARCHITECTURE.md

## 목적

이 문서는 `README.md`와 `docs/modules/*.md`를 묶어 현재 시스템이 어떻게 연결되는지 설명한다.

- 모듈 경계
- 데이터 흐름
- 런타임 흐름
- 변경 시 영향 범위

세부 구현을 모두 적기보다, 새 Agent가 어디부터 읽어야 할지 빠르게 판단할 수 있게 쓰는 것이 목적이다.

## 모듈 맵

| 모듈 | 역할 | 상세 문서 |
|---|---|---|
| 예: Auth | 로그인, 세션 확인 | `docs/modules/auth.md` |
| 예: Billing | 결제 상태 관리 | `docs/modules/billing.md` |

## 상위 계층 구조

```text
UI Layer
  화면, 입력, 표시

Application Layer
  상태 관리, 화면 연결, 진입점

Domain Layer
  핵심 규칙, 유스케이스, 조정 로직

Infrastructure Layer
  API, DB, 파일, 런타임, 외부 SDK

Static/Data Layer
  설정 파일, 번들 자산, 스키마, 문서
```

## 핵심 런타임 흐름

### 1. 시작 흐름

1. 앱 또는 서비스 시작 진입점
2. 초기 상태 로드
3. 주요 런타임 준비
4. 기본 화면 또는 기본 API 진입

### 2. 핵심 사용자 작업 흐름

1. 사용자가 무엇을 한다.
2. 어느 계층이 입력을 받는다.
3. 어떤 도메인 로직이 실행된다.
4. 어떤 저장소 또는 외부 시스템이 바뀐다.
5. 결과가 사용자에게 어떻게 돌아간다.

### 3. 백그라운드 또는 배치 흐름

1. 어떤 조건에서 실행되는지
2. 어떤 입력을 읽는지
3. 어떤 결과를 남기는지

## 저장소별 데이터 소유권
